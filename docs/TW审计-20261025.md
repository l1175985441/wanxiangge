## 三、审计抓到并已修的两条（真漏洞）

1. **人物浮层的 Esc 监听卸不掉**（`ui/sections.js`）
   原来是**匿名** `document.addEventListener('keydown', (ev) => …)`，全库找不到对应的 `removeEventListener` ⇒ 停用／卸载后它还在听。
   **修法**：抽成 `ui/esc-close.js`（`bindEscClose` / `unbindEscClose`，同一个 `handler` 句柄成对增删）；`sections` 导出 `unbindPersonCardEsc()`；`index.js` 的 `teardownUi()` 里调它。顺带把主文件从 8209 行压回 **8196 行**（硬线 8200）。

2. **等容器出现的观察器没有停止口**（`ui/wand.js`）
   `MutationObserver` ＋ 超时定时器只在“容器出现”时自己停；若插件在此之前被停用，两者都还活着。
   **修法**：导出 `stopWandWaiting()`（内部 `observer.disconnect()` ＋ `clearTimeout`），`teardownUi()` 里调。

守卫夹具：`_自测/run-tests-lifecycle.mjs` 六条（成对导出／无匿名 keydown／导出卸载／wand 真停／`teardownUi` 两个都调／manifest 无空 homePage）。

## 四、⚠️ 静态闸证明不了的（留给真机）

按技能自己的分界，下面这些**必须**在装了扩展的酒馆里验，我这里只记“没验”：

1. **能力快照**：`check-extension-capabilities.mjs` 要一份 `capability-contract.json`（我们没写）＋ 一份已安装环境的 API 快照。**我们没跑**，所以“依赖的宿主／助手函数在当前版本存在”这件事**没有静态证据**。
2. 扩展管理器里**能看见、能启用/停用、能卸载**。
3. **页面刷新后**重启是否正常（`activate` 的实际时序）。
4. 事件 payload 的实际形状（`MESSAGE_RECEIVED` 等的 `chatKey`／楼层号）。
5. 设置持久化（`extensionSettings.wanxiangge` 落盘与读回）。
6. UI 渲染（面板／工作台／浮层／两列网格／状态带）。
7. **卸载后的清理**（这次修的两条正属于此类——静态只能证明“代码成对”，⛔ 证明不了“真的卸干净了”）。
8. 目标版本：仓库 `minimum_client_version` 写的是 **1.12.0**；试验田实跑版本本轮**没有核**。
